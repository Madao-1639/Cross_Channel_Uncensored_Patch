# 架构与约定

本仓库产出一个**独立、可选叠加**的 CG 替换包。它与内容还原补丁是两个独立发布物：还原补丁负责忠实还原官方内容与汉化，本补丁只提供官方之外的替换素材。

## 产物形态

| 文件 | 安装位置 | 内容 |
|---|---|---|
| `patch.arc` | `<游戏根>\patch.arc` | 只含被替换的成员（`resource/cg/*.png`，文件名即成员名） |
| `Script.arc` | `<游戏根>\Script.arc` | Steam 原版内联，只把 `ArcFileName.lua` 换成槽位版 |

两个文件都是**新增/单文件替换**，不触碰还原补丁的任何归档，也不改 `AdvHD.exe` / DLL。

## 为什么用槽位归档而不是裸目录

引擎的归档成员解析是四级链（裸文件目录 / 用户数据根 / 语言包目录 / 游戏根目录）。裸文件目录这一层由**调用点的编译期常量**控制，CG 走的路径恒为 0，因此纯数据无法开启 —— 想把 CG 放成散文件必须改 exe。槽位归档绕开了这个限制：它改的是**归档名解析**（`ArcFileName.lua` 的返回值），不是裸文件开关。

## 为什么 `Script.arc` 是耦合点

引擎不写死归档名，每次取资源都调 `Script.arc` 里的 `ArcFileName.lua` 按资源名前缀决定归档名。要让引擎去读 `patch.arc`，只能在 `ArcFileName.lua` 里加槽位探测。

```
还原补丁：asset/*.arc（根目录层） + zh-CN/*.arc（语言包层）   不包含根目录 Script.arc
本补丁：  根目录 Script.arc（槽位版） + patch.arc
```

⇒ `Script.arc` 由本补丁拥有，是双方**唯一**的耦合点。它基本不再变动（4 个映射函数 + 槽位探测），但任何一方要改它，都必须与另一方对齐。

`Script.arc` 的基准是 **Steam 原档**（`resource/Script.steam.arc`，从 Steam 版内联而来），不依赖游戏目录当前状态、也不依赖还原补丁的产物 —— 这是把基准存档进仓库的原因。

## 为什么占据优先级最低的 `patch.arc`

槽位优先级为 `patch` < `patch2` < `patch3`（后注册优先）。本补丁占最低槽位，意味着将来任何第三方补丁可以用 `patch2`/`patch3` 覆盖本补丁的成员，而本补丁不会挡住它们。

## 只替换与脚本无关的资源

`ws2` 与其 `lng` 译文是**同一逻辑单元**（`lng` 按脚本槽位/消息下标替换文本），脚本结构一变译文必然错配。所以：

- 本补丁只替换 **CG**（以及将来可能的语音、BGM、UI 图）这类与脚本无关的资源；
- **不得**把中文译文放进槽位，也不得用它修改 `ws2`；
- 槽位对任何语言模式一视同仁，这与语言包的作用域（只服务该语言）互补而非重叠。

## 成员命名

`patch.arc` 的成员名一律**小写**。原因：引擎按名字查成员时是大小写不敏感的（`wcsicmp`），但槽位探测是**字节比较**——它会先把请求名转小写、再去归档的成员表里找同样的字节序列。若归档里写的是大写，探测就会漏判、导致本该替换的成员回落原生归档。构建脚本统一小写，`resource/cg/` 里的文件名不限大小写。

## 卸载

删除 `<游戏根>\patch.arc`，并把 `Script.arc` 还原成备份（或用 Steam 校验还原该文件）。两者都是单文件，无残留。
